# ADR-006 — Publishing Contracts and Separation of Authority

## Status

Accepted

## Decision

Studio publishes versioned structured content through a portable publishing contract.

Studio is authoritative about **what content exists and what the author intends to publish**.

The publishing destination is authoritative about **how that content is structured, interpreted, validated, and rendered**.

Schemas define the requirements and capabilities of each content type.

Studio consumes schemas generically and does not hard-code publishing-specific content types into its editor.

Studio never generates website components or presentation code.

## Separation of Responsibilities

### Studio

Studio is responsible for:

- Creating content
- Editing content
- Managing document metadata
- Managing content blocks
- Managing document lifecycle
- Knowing which schema applies to a document
- Producing the publishing contract

### Publishing Destination

The publishing destination is responsible for:

- Defining schemas
- Defining content requirements
- Validating published content
- Interpreting content types
- Rendering content
- Controlling presentation
- Controlling URLs and public presentation
- Generating website components

## Consequences

- Journal and Project can have completely different schemas.
- Adding a new publishing section does not require building a new editor.
- The same Studio can serve multiple publishing destinations.
- Website redesigns do not require changes to Studio's content model.
- Publishing destinations retain control over presentation.
- Content remains portable and framework-independent.
- Studio's editor remains generic.

## Principle

> Studio knows what. The website knows how.

Or, more formally:

> Studio is the authoring authority. The publishing destination is the publishing authority.
